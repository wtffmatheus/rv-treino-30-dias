## Administração e configuração

Copiar `.env.example` para `.env` no servidor autorizado e preencher as variáveis diretamente no ambiente seguro. Não enviar valores secretos em mensagens nem versioná-los.

1. Configurar `PUBLIC_SITE_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY` e `SUPABASE_SERVICE_ROLE_KEY` de homologação.
2. Definir ou alterar **somente `ADMIN_EMAIL`**, convidar essa conta por um canal administrativo protegido do Supabase, confirmar o e-mail e reiniciar o processo Node. Não há papel editável pelo aluno.
3. Habilitar confirmação de e-mail, SMTP e templates próprios com fragmento `#token_hash=...&type=email` ou `type=recovery`, conforme [guia do backend](../backend/SECURE_BACKEND_RV30.md).
4. Configurar o provedor aprovado e seus segredos no servidor. Manter `RV30_SALES_ENABLED=false` até terminar os testes reais.

O preço R$ 399,00 já existia no código de demonstração, mas não foi considerado aprovação comercial. No modo real, somente o preço aprovado no banco pode aparecer; sem ele a interface mostra “A confirmar”. Os 30 dias descrevem o programa, não a duração do acesso. Prazo de acesso, preço definitivo e tratamento de reembolso/contestação dependem de definição comercial.

## Publicação

`npm run build` gera somente a parte estática em `dist/`; não publica a API. O novo servidor exige Node 22+ persistente, com `npm start`, atrás de HTTPS na mesma origem das páginas. As sessões são em memória de um único processo: reiniciar exige novo login. Para múltiplas réplicas, implementar armazenamento compartilhado de sessões antes de escalar.

Se a hospedagem continuar apenas estática, rotear `/api/*` para esse serviço ou adaptar a API ao runtime escolhido antes de abrir vendas. Não publicar a raiz do repositório nem `.env`, migrações, testes ou credenciais. O CSP permite mídia assinada dos projetos padrão `*.supabase.co`; um domínio personalizado exige acrescentar a origem exata a `media-src`, sem abrir scripts ou conexões arbitrárias.

A auditoria de lançamento deve continuar **NO_GO** até comprovar pagamento, matrícula, autorização, e-mails, conteúdo privado, condições comerciais e hospedagem em homologação. Alterar uma flag no navegador não demonstra prontidão.
